# 玩家行为日志与 AI 复盘

## Skill 定位

这个 Skill 用来建立“真实行为 -> 匿名日志 -> AI 洞察 -> 产品改进”的闭环。它强调先收证据,再做分析,避免 AI 在没有日志的情况下凭感觉评价用户。

它适合交互式产品、网页游戏、培训演练、内部流程工具、活动页、问卷之外的用户路径分析。

## 适用场景

- 需要记录用户关键行为和状态变化
- 需要上线后分析卡点、误解点、流失点
- 需要把一局游戏或一次流程转成 AI 可读 payload
- 需要结局复盘、用户画像、路径诊断或体验改进建议
- 需要设计匿名日志 schema
- 需要决定哪些信息不能公开存储或展示

## 不适用场景

- 没有真实行为数据,只做玩法模拟
- 只需要验证页面/API 是否能跑
- 需要追踪具体个人身份
- 需要搭建复杂 BI 看板且已有明确指标体系

## 日志设计原则

| 原则 | 说明 |
|---|---|
| 匿名优先 | 使用 `clientId`、`sessionId`、`runId`,不记录个人身份 |
| 事件最小可用 | 先记录关键行为,不要一开始追求完整埋点体系 |
| 原始日志优先 | 先保留事件流和 session summary,后续按问题分析 |
| 状态快照辅助 | 周期性记录关键状态,用于还原卡点前后变化 |
| 选择单独记录 | 用户主动决策应和系统自动动作区分 |
| 可补传 | 上传失败时保留短队列,下次补传 |
| 可兜底 | 分析失败不影响主流程 |

## 最小事件集

| 事件 | 说明 |
|---|---|
| `session_start` | 用户进入页面或流程 |
| `ui` | 关键入口点击、tab 切换、弹窗打开 |
| `action` | 系统或用户触发的重要动作 |
| `decision` | 用户主动选择,需要保留前后变化 |
| `snapshot` | 周期状态快照 |
| `game_over` / `flow_end` | 游戏或流程结束 |
| `session_end` | 页面隐藏、关闭、主动退出 |

## 推荐字段

```text
schemaVersion
eventId
eventType
eventName
createdAt
clientId
sessionId
runId
app.version
page.path
game/state summary
payload
```

session summary 可额外包含:

- actionHistory
- decisionHistory
- diagnosticsLatest
- finalLog
- result
- duration
- currentStage

## 隐私边界

禁止记录:

- 姓名、手机号、身份证、账号
- 精确地理位置
- 支付信息
- API Key、token、cookie
- 个人聊天内容
- 可直接识别个人的组合信息

谨慎记录:

- 设备信息
- referrer
- IP 相关信息
- 过长文本输入

可记录:

- 匿名 ID
- 游戏/流程状态
- 关键行为
- 关键选择
- 阶段和任务
- 失败原因

## AI 分析流程

1. 明确分析问题,例如“新手为什么没有完成第三步”。
2. 读取一批 JSONL 原始日志。
3. 按 `sessionId` / `runId` 聚合。
4. 排除测试数据和版本不一致样本。
5. 还原关键路径时间线。
6. 找卡点信号:
   - 重复点击
   - 长时间停留
   - 频繁开关入口
   - 关键任务长期未完成
   - 失败前没有自救动作
   - 弹窗后退出
7. 引用具体证据。
8. 输出改进建议和补采字段。

## 复盘生成流程

如果日志用于生成用户复盘,必须先构建结构化 payload:

- result:最终结果
- summary:关键指标
- valueProfile:行为标签聚合
- keyDecisions:关键选择
- decisions:最近选择
- finalLog:结束前日志

AI 复盘必须满足:

- 只引用真实选择
- 不虚构原因
- 不暴露内部字段
- 不输出完整原始日志
- 失败时有本地规则兜底

## 输出模板

```text
## 日志方案

- 事件:
- 字段:
- 存储:
- 隐私边界:

## 分析结论

- ...

## 证据

| 发现 | session/run | 日志证据 | 解释 |
|---|---|---|---|

## 改进建议

- ...

## 建议补采

- ...
```

## 失败处理

| 情况 | 处理 |
|---|---|
| 日志量太少 | 只输出个案观察,不要做总体判断 |
| 版本混杂 | 按版本拆分样本,不要混合分析 |
| session/run 缺失 | 先按可用字段聚合,并建议补采 ID |
| 事件字段过粗 | 明确无法判断的环节,补充事件名或 payload 建议 |
| AI 输出无证据 | 删除无证据结论,要求重新引用日志 |
| 涉及隐私字段 | 先脱敏或排除,再分析 |
| 存储写入失败 | 检查 endpoint、权限、队列和 JSONL 路径 |

## 不要做什么

- 不要一开始就做重型 BI 后台。
- 不要把匿名日志和个人身份绑定。
- 不要让 AI 只根据最终分数评价用户。
- 不要把完整用户选择过程公开展示。
- 不要把模型评价当事实,必须保留证据。
- 不要把日志分析结果写成无法验证的心理判断。

## 可复用边界

可跨项目复用:

- 匿名事件模型
- session/run 聚合
- 原始日志到 AI 洞察
- 复盘 payload 结构
- 隐私边界

需要按项目替换:

- 状态字段
- 任务/阶段定义
- 关键行为枚举
- 复盘标签体系
- 日志存储位置
