# 前端游戏回归验证

## Skill 定位

这个 Skill 用来把“已经修改”变成“已经验证”。它关注页面能否打开、资源是否加载、交互是否可用、API 是否正确、数据是否写入、安全边界是否仍然成立。

它适合网页游戏、前端原型、活动页、内部工具、带轻量 Node 服务的静态站点。

## 适用场景

- 改了 React/Vue/HTML/CSS
- 改了本地服务或 API 路由
- 改了榜单、日志、telemetry、AI review
- 改了部署入口或静态资源路径
- 需要验证 console/pageerror/request failure
- 需要验证移动端或固定一屏布局
- 需要提交前给出可重复证据

## 不适用场景

- 只做纯文档整理
- 只做数值模拟,没有页面/API 改动
- 只需要审查 AI 文本输出
- 用户明确只问概念,不需要运行验证

## 验证前置条件

| 前置项 | 检查目的 |
|---|---|
| 入口文件 | 明确打开哪个页面 |
| 构建脚本 | 确认源码能生成产物 |
| 本地服务方式 | 避免依赖 `file://` 导致结果失真 |
| 关键 API | 明确需要请求哪些接口 |
| 数据写入位置 | 验证 JSONL、数据库或临时文件 |
| 浏览器验证方式 | 检查 console、截图、多视口 |

## 验证顺序

1. 检查 Git 状态,确认本次修改范围。
2. 运行语法检查或构建脚本。
3. 启动本地服务。
4. 请求主页面,确认 HTTP 200。
5. 打开浏览器,监听:
   - pageerror
   - console error
   - request failed
6. 执行关键交互:
   - 开始流程
   - 打开关键弹窗
   - 触发关键按钮
   - 提交或写入数据
7. 验证 API:
   - 正常请求
   - 错误路径
   - 重复提交
   - 异常数据
8. 验证数据写入:
   - JSONL 行数
   - 返回字段
   - 去重结果
9. 如涉及布局,验证多视口。
10. 输出证据和未覆盖项。

## 常见验证项

| 类型 | 验证项 |
|---|---|
| 页面 | 主入口 200、静态资源加载、无 console error |
| 构建 | 源文件能生成产物,产物不手改 |
| API | 精确路由、404 near miss、超时兜底 |
| 安全 | path traversal 403、XSS 文本清洗 |
| 数据 | JSONL 写入、重复提交去重、异常数据跳过 |
| telemetry | batch 写入、session-end 写入 |
| AI | 未配置模型时本地兜底,上游失败不阻塞 |
| 布局 | 桌面/移动端不溢出,页面级不滚动 |

## 最小 smoke test 设计

一个好的 smoke test 至少覆盖:

- 主页面是否可访问
- 静态资源是否可访问
- 一个关键 API 正常路径
- 一个错误 API 路径
- 一个数据写入路径
- 一个安全边界
- 一个失败兜底

不要求覆盖所有业务,但必须覆盖最容易被 AI 修改破坏的地方。

## 浏览器验证要求

页面或 UI 改动不能只靠构建通过。至少检查:

- 页面是否非空
- 关键按钮是否可见
- 弹窗是否遮挡正确
- 文本是否溢出
- console 是否有错误
- 移动端是否仍可操作

涉及 3D、canvas、复杂地图或游戏场景时,还要检查画面是否实际渲染,不能只看 DOM 存在。

## 输出模板

```text
## 验证环境

- 入口:
- 服务:
- 构建:

## 通过项

| 项目 | 证据 |
|---|---|

## 失败项

| 项目 | 现象 | 建议 |
|---|---|---|

## 未覆盖项

- ...
```

## 失败处理

- 构建失败:先修构建,不要继续做浏览器验证。
- 服务启动失败:查端口、路径、依赖和环境变量。
- 页面 200 但空白:查 console、bundle、root 挂载和资源路径。
- API 失败:区分路由错误、请求体错误、写入权限和上游超时。
- 截图异常:检查视口、字体、资源加载和布局约束。

## 可复用边界

可跨项目复用:

- 构建 -> 服务 -> 浏览器 -> API -> 数据写入的验证顺序
- console/pageerror/request failure 检查
- smoke test 最小覆盖原则
- 证据化输出

需要按项目替换:

- 本地服务命令
- 入口 URL
- API 路由
- 数据文件位置
- 关键交互路径
