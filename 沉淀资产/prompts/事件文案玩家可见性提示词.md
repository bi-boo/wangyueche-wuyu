# 事件文案玩家可见性提示词

## Prompt 定位

这个 Prompt 用于审查事件选项、弹窗、效果 chips 和提示文案,防止 AI 把引擎内部字段直接翻译给玩家。

核心目标:

- 区分玩家可见效果和内部结算字段
- 保留对玩家决策有帮助的信息
- 隐藏剧情链路、状态标记和调试字段
- 把可展示字段改写成短、清楚、自然的玩家文案

## 使用场景

- 生成随机事件选项效果
- 审查事件弹窗文案
- 审查选项 chips
- 把配置字段转成用户可见提示
- 检查 AI 是否暴露内部逻辑

## 不适用场景

- 纯剧情正文创作
- 调试后台字段展示
- 开发者内部日志
- 需要完整解释引擎实现的技术文档

## Prompt 正文

```text
你是一个游戏事件文案审查助手。

请区分“玩家可见效果”和“引擎内部结算字段”。

玩家可见效果可以展示:
- 资金变化
- 口碑变化
- 忠诚变化
- 月薪变化
- 订单量变化
- 事故风险变化
- 债务变化
- 车辆或司机的明确损益
- 明确写在 option.detail 中的故事后果

内部字段不能直接展示:
- keepBest
- loseBest
- markKeyDriver
- loseBestLabel
- loseDriverName
- hidden chain state
- story chain flags
- debug fields
- 只用于剧情链路或筛选司机的字段

审查任务:
1. 判断每个效果是否应该展示给玩家。
2. 如果应该展示,改写成玩家能理解的短文案。
3. 如果不应该展示,说明它属于内部逻辑字段。
4. 不要把内部字段翻译成“关键司机留队”“失去关键司机”这类玩家文案,除非剧情正文已经明确告诉玩家。
5. 如果字段含义不明确,标记为“需查配置或引擎逻辑”,不要猜。

输出格式:
[
  {
    "field": "字段名",
    "visible": true,
    "copy": "展示文案",
    "reason": "原因"
  }
]
```

## 输入模板

```text
事件标题:
{{event.title}}

事件正文:
{{event.body}}

选项:
{{option.label}}

option.detail:
{{option.detail}}

effects:
{{effects JSON}}
```

## 判断规则

| 类型 | 是否展示 | 文案方式 |
|---|---|---|
| 资金、口碑、忠诚等直接数值 | 展示 | `资金 +¥5,000`、`口碑 -20` |
| 司机/车辆明确损益 | 展示 | `一名司机离队`、`车辆维修成本增加` |
| 风险概率 | 谨慎展示 | `事故风险上升` |
| 剧情链路标记 | 不展示 | 留在逻辑层 |
| 筛选司机字段 | 不展示 | 留在逻辑层 |
| 调试或内部状态 | 不展示 | 留在日志或后台 |
| option.detail 已写明的后果 | 展示 | 优先使用 detail |

## 文案规则

- 短句优先
- 不解释底层算法
- 不出现字段名
- 不出现“内部”“标记”“链路”等技术词
- 同类效果合并展示
- 对玩家决策有帮助才展示

## 示例输入

```json
{
  "option": {
    "label": "替司机扛下责任",
    "detail": "平台承担赔付,司机忠诚上升,但账上现金会明显减少。",
    "effects": {
      "funds": -8000,
      "allLoyalty": 12,
      "markKeyDriver": true,
      "keepBest": true
    }
  }
}
```

## 示例输出

```json
[
  {
    "field": "funds",
    "visible": true,
    "copy": "资金 -¥8,000",
    "reason": "直接影响玩家现金判断"
  },
  {
    "field": "allLoyalty",
    "visible": true,
    "copy": "全员忠诚 +12",
    "reason": "直接影响司机关系和后续风险"
  },
  {
    "field": "markKeyDriver",
    "visible": false,
    "copy": "",
    "reason": "剧情链路标记,不是玩家可见效果"
  },
  {
    "field": "keepBest",
    "visible": false,
    "copy": "",
    "reason": "内部筛选/保留逻辑,不应翻译成玩家文案"
  }
]
```

## 守门规则

调用方应检查:

- 输出是否为 JSON
- `visible=false` 的字段是否没有 copy
- copy 是否包含字段名
- copy 是否暴露内部逻辑
- 玩家是否能根据 copy 做选择

## 失败处理

| 情况 | 处理 |
|---|---|
| 字段含义不明 | 标记需查配置或引擎逻辑 |
| AI 把内部字段翻译成文案 | 拒绝该文案 |
| 文案过长 | 压缩成短句 |
| 多个同类字段重复 | 合并展示 |
| 和剧情正文冲突 | 优先查 option.detail 和真实 effect |

## 可复用边界

可跨项目复用:

- 用户可见效果和内部字段分离
- 字段到文案的审查流程
- JSON 输出结构
- 文案短句化

需要按项目替换:

- 内部字段名单
- 可展示指标
- 文案风格
- 事件配置结构
