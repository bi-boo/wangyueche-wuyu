# AI 协同开发案例说明

## 项目简介

《网约车物语》是一个网页端模拟经营游戏,也是一个 AI 协同开发案例。项目实际接近“一人团队”:产品设定、玩法机制、前端实现、AI 复盘、日志采集、部署和验证都由人和 AI 协作完成。

这个案例的重点不是游戏题材本身,而是展示一个复杂想法如何被拆成可运行、可验证、可复用的产品原型。

## AI 具体参与了什么

| 环节 | 人负责什么 | AI 负责什么 | 最终产物 |
|---|---|---|---|
| 产品定义 | 设定题材、体验目标、黑色幽默基调、关键机制 | 把口头想法整理成游戏机制和文档结构 | `GAME_DESIGN.md`、`PRODUCT.md`、`DESIGN.md` |
| 玩法实现 | 判断哪些机制该保留、删减、前置或后置 | 改数据、改引擎、改 React 组件、改样式 | 可运行的网页游戏 |
| 可维护重构 | 决定不要继续堆单文件 | 将 HTML 单文件拆成 engine/app/styles 构建链 | `src/engine`、`src/app`、`src/styles` |
| 体验打磨 | 判断玩家哪里看不懂、哪里打断太多 | 优化引导、弹窗、任务、地图、司机档案、暂停菜单 | 更顺畅的一屏化游戏 UI |
| AI 复盘 | 定义“经营人格评价”的产品目标 | 记录决策,组织 payload,调用模型,解析结构化输出 | 结局后 AI 运营复盘 |
| 数据闭环 | 决定先收原始日志,不先做大看板 | 实现匿名 telemetry、JSONL 存储、session summary | 玩家行为日志系统 |
| 验证与部署 | 定义“完成前必须证明能跑” | 写 smoke server、做 API 和页面回归验证 | `scripts/smoke-server.mjs`、部署文档 |
| 复用沉淀 | 识别哪些流程能给其他团队用 | 整理 Skill、Agent、Prompt 模板 | 本目录资产包 |

## 其他团队能复用什么

### 1. AI 协同开发规则

把“AI 怎么参与项目”写成项目规则,包括:

- 先读产品文档,不要直接乱改代码
- gameplay 改动先同步设计文档
- 代码按数据、引擎、组件、样式分层修改
- 构建产物不能手改
- 完成前必须跑验证

这类规则适合所有需要长期迭代的前端原型、内部工具和活动页。

### 2. 前端回归验证 Skill

项目里已经有 `scripts/smoke-server.mjs`,能验证:

- 主页面是否能打开
- API 路由是否正确
- 榜单写入是否正常
- 重复提交是否去重
- 异常数据是否跳过
- telemetry 是否写入
- 路径逃逸是否被拒绝

这可以复用到其他前端项目,解决“AI 写完但没人知道有没有坏”的问题。

### 3. 玩家行为日志到 AI 洞察

这个项目没有一开始就做复杂 BI 看板,而是先沉淀原始行为日志:

- 关键操作
- 关键选择
- 周期状态快照
- 单局结束摘要

后续有问题时,直接用 AI 分析日志里的玩家卡点、误解点和跳出点。这对内部工具、培训演练、活动页、小游戏、流程型产品都可复用。

### 4. 结构化 AI 输出守门

AI 运营复盘不是让模型随便写一段话,而是要求模型返回固定 JSON 字段:

- `headline`
- `verdict`
- `evidence`
- `advice`

服务端再做清洗、兜底和异常数据识别。这个机制可复用到客服总结、用户画像、面试评价、复盘报告等场景。

### 5. 游戏项目方法论资产

这个项目还把游戏开发里最容易被忽略的“决策结构”沉淀成了可分享文档:

- 用 Game Pillars 控制范围,避免机制越加越多
- 用 GDD 8 节把规则、公式、边界和验收写清楚
- 用经济模型检查资金、口碑、车辆、司机、培训和奖励
- 用难度曲线和玩家旅程检查新手节奏
- 用 ADR 记录架构取舍,避免以后忘记为什么这么做

这些内容适合分享给其他产品经理或小团队:不是讲怎么写代码,而是讲怎么让 AI 协作项目变得可控。

## 可以沉淀成 Skill 的部分

| Skill | 解决什么问题 |
|---|---|
| 游戏项目 AI 协同开发 | 让 AI 按产品文档、代码分层和验证链路开发复杂前端项目 |
| 玩家行为日志与 AI 复盘 | 让 AI 从匿名日志里分析用户卡点,而不是凭感觉猜 |
| 前端游戏回归验证 | 让 AI 每次改完都自动证明页面、API、数据写入没有坏 |
| 游戏项目方法论资产 | 让 AI 把玩法、数值、UX、验证和复盘沉淀成可复用文档 |

## 可以沉淀成 Agent 的部分

| Agent | 职责 |
|---|---|
| 架构巡检 Agent | 检查代码结构、构建产物、文档事实和验证链路 |
| 玩法数值模拟 Agent | 用策略模拟检查新手节奏、资金压力、口碑流失 |
| 玩家日志洞察 Agent | 读取 telemetry JSONL,输出卡点和改进建议 |
| AI 复盘守门 Agent | 检查模型输出是否结构化、可展示、没有编造证据 |
| 游戏设计 Agent | 把新机制、新任务、新结局转成规则、边界和验收标准 |
| 经济系统平衡 Agent | 检查资金、口碑、车辆、司机、培训和奖励之间的资源流 |
| 一屏化 UX 审查 Agent | 守住主界面一屏化、信息层级、交互路径和多视口可用性 |
| 叙事文案 Agent | 统一司机、事件、结局和玩家可见文本的叙事边界 |
| QA 测试用例 Agent | 把改动范围转成测试步骤、预期结果、通过标准和回归清单 |

## 对外说明口径

这个案例的价值不是“AI 写了多少代码”,而是把一人团队的工作拆成了可复用流程:

1. 产品经理输入目标和判断。
2. AI 按规则实现、验证、记录。
3. 项目运行后继续收集行为数据。
4. 再用 AI 对真实数据做复盘。
5. 最后把流程沉淀成 Skill、Agent 和 Prompt。
6. 进一步把游戏开发方法、阶段门、角色路由和文档模板沉淀成可分享资产。

这套流程可以迁移到其他团队的内部工具、运营实验、培训演练、活动页和复杂原型开发。
